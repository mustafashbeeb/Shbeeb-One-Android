# Shbeeb One — المساعد العربي المتكامل

**Shbeeb One (شبيب ون)** هو تطبيق Android يضم واجهة المساعد العربية الأساسية، مع تجربة **AnythingLLM Mobile** المفتوحة المصدر كجزء مدمج لمساحات العمل والوثائق والنماذج. اسم المنتج هو Shbeeb One؛ أما AnythingLLM وStable Diffusion وLiteRT-LM و`llama.rn` فهي أسماء تقنيات ومشاريع طرف ثالث تُذكر حفاظاً على الإسناد والترخيص.

> **الحالة: تجريبية.** يلزم تثبيت النسخة واختبارها على جهاز Android حقيقي، خصوصاً محرك الصور المحلي والحرارة واستهلاك الذاكرة، قبل اعتبارها إصداراً مستقراً.

## ما الذي يتضمنه

- واجهة عربية بـJetpack Compose للمحادثة وإعداد المحركات والمهام والصوت وإدارة الملفات والتحكم الآمن بفتح تطبيقات الهاتف.
- AnythingLLM Mobile (React Native) لتجربة مساحات العمل والمحادثات والوثائق وPDF والنماذج المحلية التي يدعمها المصدر. يبقى هذا مكوّناً مستقلاً داخل التطبيق وليس اسم المنتج.
- محرك Shbeeb المحلي للمحادثة LiteRT-LM، ومحرك `llama.rn` في مساحة AnythingLLM؛ لا نفترض أن نموذج أحدهما يعمل تلقائياً في الآخر.
- **توليد صور محلي تجريبي** عبر `stable-diffusion.cpp` على Android arm64. لا ترفق أوزان النموذج داخل APK؛ يمكن للتطبيق تنزيل نموذج SD 1.5 إلى ملف يختاره المستخدم أو فتح ملف موجود.
- أداة فيديو محلية لإنشاء MP4 صامت بتحريك صورة. هذه أداة تحرير/تحريك وليست توليد فيديو diffusion من النص.
- تقارير عربية عن الدمج والخصوصية والتوافق والقيود في مجلد [`docs`](docs/).

## اللغة العربية في AnythingLLM

أُضيف قاموس عربي يغطي **1331 مدخلاً نصياً غير فارغ** في واجهة AnythingLLM المدمجة، وأُفعّل اتجاه RTL عند اختيار العربية. من الإعدادات افتح **Language** واختر **العربية**. قد تتطلب إعادة فتح التطبيق لتطبيق اتجاه الصفحة على كل الشاشات. الترجمة مكتملة من ناحية المفاتيح والمتغيرات، لكنها ترجمة أولية تحتاج مراجعة بشرية وتجربة على الهاتف قبل اعتبار كل صياغة نهائية.

## نموذج الصور المحلي

الملف التجريبي المقترح هو [`stable-diffusion-v1-5-pruned-emaonly-Q4_0.gguf`](https://huggingface.co/second-state/stable-diffusion-v1-5-GGUF) بحجم **1,566,768,416 بايت (نحو 1.57 GB)**. التطبيق يتحقق من الحجم وبصمة SHA-256 قبل اعتماد الملف. أوزان النموذج ليست ضمن المستودع أو APK، وترخيص الأوزان **CreativeML OpenRAIL-M** منفصل عن ترخيص شفرة التطبيق؛ راجع شروط النموذج قبل الاستخدام أو إعادة التوزيع.

يمكن تنزيل الملف مباشرة إلى مجلد يختاره المستخدم عبر منتقي Android، أو اختيار نسخة موجودة. يتطلب التشغيل ملفاً محلياً قابلاً للقراءة؛ وتبقى صلاحية الوصول إليه ضمن آلية Android. النموذج مخصص للصور وليس نموذج محادثة. جودة فهم الأوصاف العربية أقل من الإنجليزية في SD 1.5، ولم تُقَس السرعة أو الحرارة بعد على OPPO Find X5.

## مشاركة نموذج المحادثة بصيغة GGUF

يمكن اختيار مجلد مشترك لتنزيل نماذج GGUF الخاصة بمزوّد `llama.rn` مباشرةً إليه، أو ربط ملف موجود دون نسخه. يختار المستخدم الملف نفسه من منتقي Android في التطبيق الآخر ويمنحه إذناً منفصلاً؛ يجب أن يكون التطبيق الآخر متوافقاً مع GGUF وبنية النموذج وتكميمه. هذه الميزة لا تجعل GGUF محرك LiteRT-LM ولا تصلح ملفات GGUF المخصصة لتوليد الصور كموديلات محادثة. راجع [دليل مكتبة GGUF المشتركة](docs/SHARED_GGUF_LIBRARY_AR.md).

## الفيديو: الحد التقني بوضوح

ميزة الفيديو الحالية تنشئ MP4 محلياً من صورة، لكنها **لا تدّعي توليد مشاهد فيديو بالذكاء الاصطناعي**. نموذج الفيديو Wan2.1-T2V-1.3B منخفض الدقة يتطلب حزمة أوزان مساعدة كاملة تقارب **4.725 GB** وفق ملف النموذج، وتذكر قياسات الناشر على بطاقة رسومية خادمية ذروة تخصيص GPU تقارب **7.078 GiB** حتى مع تكميم Q4 محسّن. هذه القياسات ليست أداء هاتف، وذاكرة OPPO Find X5 الفعلية 8GB مشتركة مع Android والتطبيقات؛ لذلك لن نعرض Wan كميزة احترافية مضمونة على هذا الهاتف أو نحمّله تلقائياً.

## الخصوصية

- لا تُدرج مفاتيح توقيع أو `google-services.json` أو أسرار Firebase في المستودع.
- إرسال Telemetry وتقارير Firebase/Crashlytics معطّل في هذا البناء.
- عند تنزيل النموذج، يتصل التطبيق بمصدره العام فقط بعد اختيارك للتنزيل ومجلد الحفظ؛ يتحقق من بصمة الملف.
- التوليد المحلي للصورة لا يرسل الوصف إلى مزود سحابي. التوليد السحابي عبر OpenAI منفصل واختياري، ويعرض تأكيداً قبل إرسال الوصف وقد يترتب عليه رسم API.
- مزود سحابي أو خادم Ollama يختاره المستخدم يرسل الطلبات لذلك المزود؛ الاستدلال المحلي يحتاج نموذجاً متوافقاً.
- يسمح Android بطلبات HTTP غير المشفرة لدعم خادم محلي يختاره المستخدم مثل Ollama؛ لا تستخدم ذلك على شبكة عامة غير موثوقة، وفضّل HTTPS للخوادم البعيدة.
- البحث على الويب متوقف افتراضياً؛ تفعيله يرسل عبارة البحث إلى You.com. تحديد الموقع الشبكي معطل.

## البناء من المصدر

المتطلبات: JDK 17 أو أحدث (تم اختبار إعدادات المشروع على JDK 21)، Node.js 20.19.5، Yarn Classic 1.22.22، Android SDK Platform 36، Build Tools 36.0.0، NDK 27.1.12297006 وCMake 3.22.1. إعداد Android المحلي مثل `local.properties` يبقى خارج Git.

```bash
git clone https://github.com/mustafashbeeb/Shbeeb-One-Android.git
cd Shbeeb-One-Android
git submodule update --init --recursive
yarn install --frozen-lockfile
./gradlew :app:assembleRelease
```

الناتج `app/build/outputs/apk/release/app-release.apk`. يتضمن APK حزمة JavaScript والمكتبة الأصلية لمحرك الصور، لذلك لا يحتاج إلى Metro. أوزان النماذج لا تدخل في APK. يقتصر ABI الحالي على `arm64-v8a`. رقم حزمة Android `com.shbeeb.ai` بقي ثابتاً لحماية التوافق مع النسخ السابقة.

للتطوير الحي عبر Metro: شغّل `yarn start` وثبّت نسخة Debug وفق تعليمات React Native. حزمة Release الحالية للاختبار فقط وموقّعة بمفتاح Android debug؛ لا تستخدمها للنشر التجاري. قد يلزم إزالة نسخة سابقة موقعة بمفتاح مختلف قبل تثبيتها.

## التحقق الآلي والتنزيل

يشغّل GitHub Actions فحص TypeScript، وتطابق ملفات الترجمة، وESLint، واختبارات JavaScript، واختبارات Android وLint، ثم يبني APK مستقلاً ويجهز ZIP مع تعليمات عربية وبصمة SHA-256. اسم artifact هو `shbeeb-one-android-standalone-package`؛ التنزيلات تظهر في تبويب **Actions → التشغيل الناجح → Artifacts**.

قبل اعتماد أي APK: اختبر فتح التطبيقين، تحميل النموذج من ملف SAF، توليد صورة محلياً، إلغاء التوليد، حفظ PNG، ودرجة الحرارة والذاكرة على الهاتف المستهدف. نجاح البناء وحده لا يثبت نجاح تشغيل النموذج أو سرعة أدائه على الهاتف.
