# دمج AnythingLLM Mobile داخل Shbeeb One

**المنتج:** Shbeeb One (شبيب ون)، تطبيق Android عربي.
**المستودع:** [mustafashbeeb/Shbeeb-One-Android](https://github.com/mustafashbeeb/Shbeeb-One-Android).
**فرع التطوير:** `feature/on-device-media-generation`.
**الإصدار:** 0.12.0 تجريبي، `versionCode 19`، Android package `com.shbeeb.ai`.

## الحالة الراهنة

أُعيد بناء واجهة Shbeeb الأساسية بـJetpack Compose لتبدأ بالمساعد، ثم الاستوديو والأدوات والإعدادات. بقيت شفرة AnythingLLM Mobile (React Native) ومكتبة GGUF المشتركة ضمن المشروع، لكن مدخل واجهتها مخفي مؤقتاً: المستخدم سبق أن أبلغ أن الدخول إلى AnythingLLM يغلق التطبيق. لا يوجد لدينا سجل من هاتفه يثبت السبب الجذري، لذلك لا أصف العطل بأنه أُصلح.

أضيفت سجلات محلية في Android Logcat للنشاط `AnythingActivity` ولأخطاء React Native غير المعالجة، ورسالة Android احتياطية في حالات الفشل المتزامن التي يمكن التقاطها. إرسال Firebase/Crashlytics وTelemetry معطل. يفيد Logcat التشخيص، لكنه لا يضمن التقاط كل انهيار أصلي يحدث خارج مسار الأخطاء المعالجة.

## ما الذي يتضمنه الدمج؟

شفرة AnythingLLM Mobile الأصلية تظل تجربة React Native مستقلة ضمن تطبيق Shbeeb One، وتشمل مساحات العمل والوثائق وPDF و`llama.rn` وفق المصدر المدمج. محرك LiteRT-LM في واجهة Shbeeb مسار منفصل؛ لا يدمج ذلك المحرك تلقائياً مع AnythingLLM ولا يجعل أحد صيغتي النموذج متوافقة مع الأخرى.

تستعمل مكتبة GGUF المشتركة Android Storage Access Framework (SAF) لربط ملف GGUF أو تنزيله إلى مجلد يختاره المستخدم، من دون اشتراط نسخة إضافية خاصة بالتطبيق. على كل تطبيق يراد منه الوصول إلى الملف أن يختاره بنفسه من منتقي Android ويمنحه المستخدم الإذن المناسب. هذه الوظيفة موجودة في جسر AnythingLLM، لكن لا يمكن الوصول إليها من التنقل الجديد بينما تبقى شاشة AnythingLLM مخفية.

أما محرك LiteRT-LM الأصلي فيقبل `.litertlm` فقط. عند أول استخدام ينسخ Shbeeb النموذج المحدد إلى ملف خاص داخل مساحة التطبيق بامتداد `.litertlm` لأن مسار SAF من نوع `/proc/self/fd/...` لم ينجح مع فحص الامتداد في LiteRT-LM. يحتاج ذلك مساحة مؤقتة/داخلية تقارب حجم النموذج + 128 MB، ولا يعدّل الملف المشترك الأصلي. لا يعمل GGUF عبر LiteRT-LM، ولا يشغّل GGUF المخصص للصور كمحادثة.

## الوسائط والصوت

- يضم التطبيق `stable-diffusion.cpp` لـ`arm64-v8a`؛ الأوزان غير مرفقة مع APK. يمكن اختيار أو تنزيل ملف Stable Diffusion 1.5 التجريبي (نحو 1.57 GB) إلى المكان الذي يحدده المستخدم. التوليد محلي بدقة 512×512 وعلى CPU، لكن لم يُختبر الأداء والحرارة على OPPO Find X5.
- ينشئ محرر الفيديو الحالي MP4 صامتاً عمودياً مدته 8 ثوانٍ من صورة واحدة. ليس توليد فيديو diffusion أو تحريك شخصيات بالذكاء الاصطناعي.
- جلسة الصوت عند الطلب تتناوب بين الكلام وتحويله إلى نص ثم رد مقروء صوتياً؛ ليست محادثة ثنائية الاتجاه متزامنة أو ميكروفوناً دائماً. قد تتطلب خدمة التعرف على الكلام في Android اتصالاً بالشبكة أو حزمة لغة.

## اللغة والخصوصية والتراخيص

واجهة Compose الجديدة وتعليماتها عربية. أضيف ملف ترجمة عربي لواجهة AnythingLLM يضم 1331 قيمة نصية غير فارغة؛ تحتاج صياغته واتجاه RTL إلى مراجعة بشرية وتجربة على الهاتف.

تتطلب كل رسالة من محرك محادثة سحابي موافقة المستخدم داخل واجهة Shbeeb الجديدة، وقد تستهلك رصيد API أو يترتب عليها رسم. لا تُرسل الرسائل في وضع LiteRT المحلي إلى خدمة محادثة سحابية. مفاتيح API تُحفظ عبر Android Keystore، وحفظ المحادثات اختيارياً ومغلق افتراضياً وغير مشفر تشفيراً خاصاً. أخطاء البدء تُسجّل محلياً فقط؛ لا تُرفع تلقائياً.

المشروع المركب يتضمن AnythingLLM المرخص بـGPL-3.0-or-later ومكوّنات أخرى لها إشعارات منفصلة؛ راجع `LICENSE` و`THIRD_PARTY_NOTICES.md`. أوزان النماذج تخضع لتراخيص منفصلة عن تراخيص الشفرة.

## التحقق في هذه البيئة

نجحت `yarn typecheck`، واختبارات `:app:testDebugUnitTest`، وبناء `:app:assembleDebug` و`:app:assembleRelease` للإصدار 0.12.0، و`:app:lintDebug`. اجتاز APK توقيع APK Scheme v2، ويحوي `assets/index.android.bundle` ومكتبة الصور `lib/arm64-v8a/libshbeeb_media.so`. اجتاز ESLint بلا أخطاء، مع 88 تحذيراً، واجتاز `git diff --check`.

هذه نتائج مصدر وبناء فقط. لم يُفتح التطبيق على جهاز OPPO، ولم يُحمّل LiteRT أو GGUF فعلياً، ولم يُولد نموذج SD صورة على الهاتف. ولم يُعد اختبار شاشة AnythingLLM لأن مدخلها مخفي في هذه النسخة. لتشخيصه، افتح Android Studio Logcat وابحث عن `ShbeebAnythingActivity` أو `Shbeeb One React Native global error`، وامسح أي بيانات خاصة من السجل قبل مشاركته.

## الخطوات التالية

1. اختبار APK 0.12.0 على الهاتف: تثبيت وتحديث، واجهة RTL، اختيار نموذج LiteRT، محادثة محلية فعلية، ثم اختبار الصورة والفيديو والصوت وقياس الذاكرة والحرارة.
2. إذا أراد المستخدم إتاحة AnythingLLM، يجمع سجل Logcat من لحظة فتحه، ثم يُحدّد هل الخطأ JavaScript أم مكتبة/وحدة Android أصلية قبل إعادة المدخل إلى التنقل.
3. بعد استقرار النشاط، اختبار مساحة العمل والوثائق وPDF وتنزيل GGUF إلى المجلد المشترك ثم اختيار الملف نفسه في تطبيق متوافق.
4. دفع الإصدار إلى GitHub والتحقق من Actions وartifact/ZIP، ثم استعمال مفتاح توقيع إنتاجي محفوظ خارج المستودع قبل أي نشر تجاري.
