# دمج AnythingLLM Mobile داخل Shbeeb AI

**تاريخ التنفيذ:** 17 نوفمبر 2026  
**الفرع المحلي:** `integration/anythingllm-gpl`  
**الحالة:** المصدر مدمج في مستودع GitHub عام مستقل. النسخة السابقة Debug كانت تحتاج Metro؛ بُني محلياً APK Release تجريبي ويحتوي JavaScript bundle. ما زال فحص GitHub Actions واختبار الهاتف الفعلي مطلوبين.

## الخلاصة

أُضيف تطبيق AnythingLLM Mobile المرخّص بـGPL-3.0-or-later إلى مشروع Shbeeb بطريقة **Brownfield**: بقي تطبيق Shbeeb الأصلي (Kotlin/Compose) هو نقطة التشغيل، وأُضيفت شاشة React Native مستقلة تُفتح من بطاقة **AnythingLLM** في الصفحة الرئيسية. لم يُستبدل `MainActivity`، ويُرفع فرع الدمج إلى مستودع عام مستقل بطلب المالك، دون تعديل مستودع Shbeeb الأصلي.

التكامل يجلب طبقة المحادثات ومساحات العمل والملفات/استخراج PDF والاسترجاع المعزز بالمستندات، إضافة إلى محرك `llama.rn` المحلي وقاعدة المتجهات ObjectBox والوحدات الأصلية اللازمة. هذه قدرات من المصدر المنقول؛ لم أتحقق منها على جهاز فعلي في هذه البيئة. يظل محرك Shbeeb المحلي LiteRT موجوداً مستقلاً عن محرك AnythingLLM.

## ما تغيّر لحماية الخصوصية

- لم تُنقل ملفات `google-services.json` أو مفاتيح التوقيع أو أسرار Firebase، ولم تُضف إضافات Firebase إلى Gradle.
- أُبقيت واجهة Telemetry للتوافق مع مكونات المصدر، لكن تسجيل الاستخدام والأخطاء محلي فقط ولا يُرسل إلى Firebase أو خادم AnythingLLM.
- البحث على الويب **معطّل افتراضياً**. إذا فعّله المستخدم من إعدادات الأدوات، تُرسل عبارة البحث إلى You.com؛ أُزيل مفتاح SearXNG العام ورابط الخادم الوسيط التابع لـAnythingLLM.
- عُطّل تحديد الموقع الشبكي؛ لا يُرسل عنوان IP لاستخراج الموقع إلى خدمة خارجية.
- عُطّل فحص التحديثات الخارجي، وأصبحت بطاقات الجولة نصية محلية بلا تحميل وسائط من CDN المصدر.
- استُبدلت روابط المشكلات ومعلومات التعريف بمستودع Shbeeb، وأُزيلت روابط الشروط والخصوصية الخاصة بالمصدر لأنها لا تمثل سياسة Shbeeb. أُضيف رابط رخصة GPL ومصدر AnythingLLM.
- الرسائل إلى نموذج سحابي أو خادم يختاره المستخدم ما زالت تُرسل إلى ذلك المزود عند استخدامه؛ التشغيل المحلي يتطلب إعداد/تحميل نموذج مناسب.

## النماذج المحلية ومشاركة النموذج بين التطبيقين

يستخدم AnythingLLM Mobile المدمج محرك `llama.rn`، ويحفظ النماذج المحلية بصيغة **GGUF** داخل مساحة التطبيق الخاصة، عادةً تحت `DocumentDirectoryPath/models/gguf/<الناشر>/<المستودع>/<الملف>`. إذا كان النموذج قد نُزّل في تطبيق AnythingLLM منفصل على الهاتف، فلن يستطيع Shbeeb قراءة مسار ذلك التطبيق تلقائياً بسبب عزل Android لبيانات التطبيقات. يمكن تنزيل النموذج مجدداً من شاشة اختيار النموذج داخل AnythingLLM المدمج، أو تصديره/نسخه إلى ملف يتيحه المستخدم ثم استيراده.

محرك Shbeeb الأصلي يستخدم LiteRT-LM ويتوقع ملفات `.litertlm`؛ لا تتحول ملفات GGUF إلى LiteRT بمجرد تغيير الامتداد. لاستخدام GGUF عبر تبويبات Shbeeb يحتاج المشروع إلى طبقة موحدة تربط واجهات Shbeeb بمحرك `llama.rn`؛ هذا الربط الشامل لم يُنفّذ بعد. وستظل قدرات الصور/الصوت/الفيديو محتاجة إلى نماذج أو مزودات تدعم كل مهمة.

## الصلاحيات والسلوك الذي يحتاج انتباه المستخدم

أُضيفت صلاحيات الكاميرا والميكروفون والتقويم والإشعارات والتنبيهات، إضافة إلى صلاحيات الإنترنت والتوافق مع تخزين Android الأقدم. يفترض أن تطلب الميزات الحساسة إذن التشغيل عند استخدامها، وليس بمجرد فتح التطبيق. كما سُجّلت خدمات المساعد الرقمي وميزة اختيار النص؛ **لن تصبح AnythingLLM المساعد الافتراضي للنظام إلا إذا اختارها المستخدم بنفسه من إعدادات Android**.

بقي `usesCleartextTraffic=true` الموجود في إعداد Shbeeb لدعم خادم Ollama المحلي. هذا الإعداد واسع؛ يُستحسن تقييده قبل إصدار عام إذا لم تعد الاتصالات المحلية عبر HTTP مطلوبة.

## التوافق والبناء

- Gradle Wrapper: **8.14.3**.
- Android Gradle Plugin: **8.13.2**.
- Kotlin/Compose plugin: **2.3.0**.
- `compileSdk`: **36**؛ `targetSdk`: **35**؛ الحد الأدنى: **Android 8 / API 26**.
- NDK: **27.1.12297006**؛ ABI المضَمّن حالياً: **ARM64 فقط**.
- يحتاج البناء إلى JDK 21، وAndroid SDK Platform 36، وBuild Tools 36.0.0، وNDK المذكور. يوقّع APK الاختبار بمفتاح Android debug الافتراضي لتسهيل التثبيت؛ هذا ليس مفتاح نشر ولا يصلح لإصدار إنتاجي.

أوامر التجربة بعد تثبيت الأدوات وقبول تراخيص Android SDK على جهاز التطوير:

```bash
yarn install --frozen-lockfile
./gradlew :app:assembleRelease
```

الناتج `app/build/outputs/apk/release/app-release.apk` يتضمن `assets/index.android.bundle` ويعمل على الهاتف دون Metro أو اتصال USB بالكمبيوتر. نسخة Debug (`assembleDebug`) مخصصة للتطوير الحي وتتوقع Metro؛ لا توزعها كتطبيق مستقل. إذا احتجت التطوير الحي، شغّل `yarn start` ثم ثبّت نسخة Debug.

## نتائج التحقق في بيئة العمل

- `npx react-native config`: نجح، واكتشف 32 اعتماداً أصلياً قابلاً للربط.
- حزمة Metro لأندرويد: نجحت؛ خرج bundle بحجم يقارب 21 MB مع 47 ملف أصل.
- TypeScript: نجح (`yarn typecheck`).
- اختبارات Jest: **6 مجموعات و74 اختباراً ناجحة**.
- فاحص الترجمة: نجح؛ القواميس متسقة.
- ESLint: لا توجد أخطاء؛ بقيت 88 تحذيراً.
- ملفات XML ومراجع الأنشطة والخدمات: اجتازت الفحص البنيوي.
- نجح GitHub Actions السابق في TypeScript وJest (74 اختباراً) واختبارات Android وLint وبناء APK Debug ورفع artifact.
- كشف اختبار المستخدم على الهاتف أن APK Debug المرفوع لا يحمل JavaScript bundle؛ رسالة «Unable to load script» تطلب Metro. هذه مشكلة في اختيار نوع البناء للتوزيع التجريبي، وليست عطلاً في الاتصال بنموذج الذكاء الاصطناعي.
- نجح `:app:assembleRelease` محلياً بعد إضافة اعتماد مزامنة أصول llama قبل bundle. تحققنا من وجود `assets/index.android.bundle` داخل APK ومن تطابقه مع الناتج المُولّد؛ حجمه **19,781,156 بايت**. وُلد APK بحجم يقارب **74 MB**.
- تحديث CI ليبني Release ويرفعه ما زال مطلوباً. لا يوجد بعد اختبار تثبيت/تشغيل على جهاز فعلي؛ لذلك لا تُعتبر هذه النتيجة اعتماداً للنشر.

## حدود معروفة وخطوات تالية

1. واجهة Shbeeb الرئيسية عربية، لكن المصدر المنقول لا يحتوي قاموساً عربياً؛ قائمة اللغات المتاحة فيه لا تشمل العربية، لذا قد تظهر شاشة AnythingLLM بالإنجليزية حتى تُضاف ترجمة عربية كاملة.
2. البناء الحالي Android فقط وARM64 فقط؛ لا يوجد تكامل iOS ضمن هذا العمل.
3. ثبّت APK المستقل بعد إتمام CI، وافتح شاشة AnythingLLM دون تشغيل Metro، ثم اختبر الاتصال بخادم/نموذج وإنشاء مساحة عمل واستيراد PDF على جهاز حقيقي.
4. قبل توزيع التطبيق، راجع التزامات GPL-3.0-or-later وتراخيص الاعتماديات، هيّئ توقيع Shbeeb الخاص، وقيّد cleartext traffic، ثم نفّذ اختبار أمان وخصوصية للإصدار الموقّع.
