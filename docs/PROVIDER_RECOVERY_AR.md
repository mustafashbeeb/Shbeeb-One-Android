# إصلاح اتصال المحركات في SHBEEB AI — 0.10.5 (تجريبي)

## ما الذي تغير؟
- أضيف مزودا **DeepSeek** (النموذج الافتراضي `deepseek-flash`) و**OpenRouter** (النموذج الافتراضي `openrouter/free`).
- لكل مزود مفتاح مشفر مستقل باستخدام Android Keystore، دون تضمين الأسرار في APK.
- تُعرض رموز HTTP وأوصاف آمنة بدلاً من رسالة عامة أو استجابة خام قد تحتوي على بيانات حساسة.
- عُزل دعم Chat Completions المتوافق مع OpenAI لـ DeepSeek وOpenRouter، بينما بقي OpenAI على Responses API.
- يظل فحص GET دون تكلفة توليد نصي. **فحص رسالة فعلية** زر منفصل يتطلب موافقة واضحة وقد يستهلك من الرصيد أو الحصة المجانية.
- لم تُغيّر أسماء قواعد بيانات المحادثات أو إعدادات المحركات السابقة، ولا يوجد حذف تلقائي.

## طريقة الاختبار على الهاتف
1. ثبّت APK اختبارياً من GitHub Actions **فقط بعد نجاح الاختبارات والبناء**.
2. من المساعد اختر المحرك، ثم افتح الإعدادات وأدخل مفتاح API الخاص به. اشتراكات الدردشة الشخصية لا تعطي بالضرورة رصيد API.
3. اختر اسم النموذج المتاح على حسابك (لـ OpenRouter ابدأ بـ `openrouter/free`).
4. اضغط «فحص اتصال المحرك بدون توليد مدفوع». هذا يتأكد من المفتاح والخدمة/معلومات النموذج، ولا يضمن الرصيد أو نجاح المحادثة.
5. للحصول على نتيجة أدق، اضغط «اختبار رسالة حقيقية (قد يستهلك رصيداً)»، وافق على الإرسال، ثم راجع النتيجة الظاهرة ورمز HTTP إن فشل.
6. جرّب سؤالاً عربياً قصيراً في شاشة المحادثة؛ تأكد من أن الخطأ لا يكشف المفتاح، ولا تتشارك أي مفتاح في صورة أو تذكرة دعم.

## قراءة الأسباب
- `401` أو "API key not valid": مفتاح خاطئ أو غير مسموح.
- `402` أو "credit balance" أو `insufficient_quota`: رصيد/ميزانية.
- `403`: صلاحيات أو قيود وصول.
- `404`: نموذج أو مسار غير متاح.
- `429`: حد طلبات، أو حصة منتهية بحسب رمز الخدمة.
- DNS / TLS / Timeout: مشكلة اتصال محلي أو شهادة أو مهلة.
- نجاح GET مع فشل POST: افحص الحصة أو الرصيد أو صيغة الطلب؛ لا يُعتبر GET إثباتاً للتوليد.

## المجاني وغير المحدود
- OpenRouter يوفر نماذج مجانية محدودة الطلبات؛ `openrouter/free` يختار نموذجاً مناسباً بحسب التوفر. استخدام API **ليس بلا حدود**.
- DeepSeek API مدفوع بحسب الاستخدام، ولا يعني نشر أوزان مفتوحة أن استضافة API مجانية.
- التشغيل المحلي على الهاتف يمكن أن يعمل دون تكلفة لكل رسالة بعد استيراد ملف `.litertlm` قانوني ومتوافق.
- **لا يحتوي APK على أوزان أي نموذج**؛ الاختبار المحلي لم ينجح بعد على هاتف المالك. حمّل نموذجاً صغيراً بترخيص مناسب واستورده يدوياً كما هو موضح في `docs/LOCAL_LM_SETUP_AR.md`.
- ملفات `.gguf` لا تعمل مباشرة في محرك LiteRT-LM الحالي، ويمكن استخدام GGUF بصورة منفصلة مع Ollama على الكمبيوتر.

## حدود التحقق
اجتياز CI يثبت نجاح اختبارات JVM وLint وتجميع APK فقط. لا يوجد هنا مفاتيح API حقيقية، ولا يمكن إثبات نجاح المحادثة السحابية أو المحلية على الجهاز قبل تجارب فعلية من المالك.
