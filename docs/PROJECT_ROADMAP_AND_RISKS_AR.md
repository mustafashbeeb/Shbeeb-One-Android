# المرجع الأساسي وخطة تطوير «مصنع الذكاء شبيب»

**التاريخ:** 16 نوفمبر 2026  
**الحالة:** وثيقة عمل مرجعية قابلة للتعديل — ليست إعلان اكتمال التطبيق  
**المالك:** صاحب مشروع SHBEEB AI

## 1. الرؤية والقواعد الثابتة
إنشاء منظومة ذكاء اصطناعي عربية، خصوصية أولاً، على هاتف أندرويد ثم الكمبيوتر، باسم «مصنع الذكاء شبيب»، مع مساعد اسمه الافتراضي «المساعد الذكي» وقابل لتغيير الاسم. واجهة بنمط بنفسجي ملكي زجاجي، إضاءة ناعمة ولمسات ذهبية وشعار SHBEEB التُرسي المعتمد بصرياً من الصور المرجعية. الالتزام بسهولة الاستخدام والسرعة، وعدم ادّعاء وجود أدوات ما زالت قيد التطوير.

أولوية التشغيل محلياً متى كان عملياً؛ لا اشتراك إجباري ولا عدّاد رسائل تفرضه واجهة التطبيق للمحادثات المحلية، مع احترام حدود العتاد والنموذج. السحابة اختيارية صريحة؛ لكل مزوّد تكاليفه وقيوده. الخصوصية والصلاحيات المحدودة والتأكيد قبل الإجراءات الحساسة شروط أساسية.

## 2. حالة الإنجاز الموثّقة (2026-11-16)
- مستودع GitHub خاص `mustafashbeeb/Shbeeb-AI`، فرع التطوير `feat/android-foundation-v1`، وطلب دمج تجريبي مفتوح.
- تطبيق Kotlin وJetpack Compose بواجهات عربية RTL: الرئيسية، المساعدة، حالة المحركات، الإعدادات، وصفحات تمهيدية للأدوات.
- حفظ اسم المساعدة محلياً في SharedPreferences.
- إصدار واجهة 0.2: خلفيات وبطاقات بنفسجية، حواف مضيئة، لمسات ذهبية، تعديل منطقة الرأس وشريط التنقل، واستخدام حواف أندرويد الآمنة `statusBarsPadding` و`navigationBarsPadding`.
- بناء آلي ناجح يوم 16 نوفمبر 2026: GitHub Actions run `43867469429`، commit `764b3956939dbce724e0aac91ffad53f062c0332`. ملف `shbeeb-ai-debug-apk` متوفر ويتضمن `app-debug.apk`.
- نجاح بناء APK **لا يثبت** ملاءمة الشكل أو الاستقرار الفعلي على هاتف المستخدم؛ اختبار النسخة 0.2 على الجهاز لم يُؤكد بعد.
- الشعار الحالي في التطبيق تقريب برمجي؛ شعار الصور المرجعية عالي الجودة لم يُدمج كأصل نهائي بعد.
- غير منفّذ بعد: محرك LLM محلي أو سحابي فعّال، صوت، توليد صور وفيديو، ملفات وذاكرة حقيقية، وأتمتة الهاتف.

## 3. الإيجابيات المستهدفة على المدى الطويل
1. قابلية العمل دون اتصال في وظائف المساعدة المحلية، بخصوصية أكبر وتكاليف تشغيلية أقل.
2. استقلالية معمارية وإمكانية تبديل النماذج ومحركات الصوت دون تغيير الواجهة.
3. منتج عربي خاص الهوية يمكن تطويره على الهاتف والكمبيوتر.
4. قابلية إضافة الصوت والذاكرة والملفات وأدوات الإنتاج وأتمتة آمنة.
5. فرصة تجارية مستقبلية بعد إثبات فائدة وأداء واستقرار حقيقيين؛ ليست ضماناً للربح.

## 4. السلبيات والعقبات
- النماذج المحلية الكبيرة تستهلك RAM والبطارية وقد ترفع الحرارة، خصوصاً على الهاتف.
- قدرات النماذج الصغيرة أقل من النماذج السحابية القوية في مهام معقدة؛ دقة العربية والصوت تحتاج قياساً عملياً.
- توليد فيديو عالي الجودة محلياً على الهاتف غير واقعي كشرط أساسي؛ نحتاج كمبيوتر قوي أو سحابة اختيارية قد تكلف مالاً.
- قيود أندرويد والصلاحيات وسياسات التطبيقات تمنع ضمان التحكم الكامل أو الاستماع الدائم بالخلفية.
- توسع الميزات يزيد تكلفة الصيانة والاختبار والأمان.
- تحديث APK من توقيعات Debug مختلفة قد يفشل بدون إلغاء تثبيت؛ نظام توقيع ثابت شرط قبل الاعتماد على تحديثات متكررة.
- يجب مراجعة تراخيص كل نموذج وكود وصوت وخدمة، خاصة عند البيع أو التوزيع؛ المجانية لا تعني الترخيص التجاري.
- حدود استخدام GitHub Actions للمستودعات الخاصة وتكاليف البنية والسحابة غير مضمونة مجاناً إلى الأبد.
- المنافسة قوية؛ التميز يجب أن يكون بالوظيفة والموثوقية لا الشكل فقط.

## 5. المراحل وخطوة قبول كل مرحلة
### المرحلة 1 — واجهة الهاتف وتثبيت الهوية (الحالية)
- اختبار APK 0.2 على OPPO Find X5 فعلياً؛ التأكد من عدم تداخل شريط أندرويد، وجود تنقل صحيح، وضوح العربية، وسلامة حفظ الاسم.
- مطابقة الشعار والألوان والزجاجيات مع المرجع البصري، وضبط التباين وأحجام الشاشات.
- **معيار الانتقال:** اختبار مستخدم ناجح ولقطات شاشة خالية من مشاكل التداخل والتعطل.

### المرحلة 2 — محادثة محلية حقيقية
- تقييم نموذج لغوي صغير ومضغوط ومحرك تشغيل محلي بترخيص مناسب.
- قياس سرعة الرد بالعربية، الاستهلاك، حرارة الجهاز، والذاكرة.
- **معيار الانتقال:** محادثة فعلية دون إنترنت على الهاتف بأداء مقبول ومقاييس موثقة.

### المرحلة 3 — البيانات والذاكرة
- حفظ المحادثات والملفات محلياً مع حذف/تصدير واضح، وتشفير البيانات الحساسة عند الحاجة.
- **معيار الانتقال:** استعادة واختبار محادثات بدون فقدان بيانات بعد إعادة التشغيل.

### المرحلة 4 — الصوت
- كلام إلى نص ونص إلى كلام بالعربية مع أذونات واضحة، مع فحص ضجيج الخلفية دون وعود بفصل صوت المستخدم كلياً.
- **معيار الانتقال:** اختبارات دقة واستجابة وأمان موثقة.

### المرحلة 5 — الأدوات والتحكم
- البدء بمهام مفيدة وآمنة، مع موافقات صريحة قبل الإرسال/الحذف/التنفيذ الحساس.
- **معيار الانتقال:** صلاحيات محدودة، وسجل تنفيذ، واختبارات عدم تنفيذ غير مقصود.

### المرحلة 6 — الصور والفيديو والكمبيوتر
- إضافة استوديو إبداعي بتكاملات محلية على العتاد الملائم أو سحابية اختيارية، مع بيان تكلفة وقيود كل وحدة.
- **معيار الانتقال:** نتائج قابلة للتكرار وجودة مفيدة وتكلفة معلومة.

### المرحلة 7 — النشر التجاري
- مراجعات أمن وخصوصية وتراخيص، توقيع إنتاجي ثابت، تحديثات، اختبار أجهزة متعددة، وشروط وتراخيص المنتج.
- **معيار الانتقال:** نسخة مستقرة قابلة للتوزيع وليست Debug.

## 6. منهج العمل والتوثيق
- كل ميزة: نطاق محدد → كود → بناء ناجح → اختبار على الجهاز → قبول المستخدم → تحديث هذا المرجع.
- عدم اعتبار نجاح GitHub Actions إثباتاً لعمل الوظيفة على هاتف حقيقي.
- توثيق الأخطاء والتكاليف والتراجعات، وإبقاء الأدوات غير المنفذة موسومة بوضوح.
- هذه الوثيقة هي **مرجع المشروع على فرع التطوير**؛ تُحدّث مع التقدم، ويُراجع نقلها للفرع الرئيسي عند اعتماد المرحلة.

### شروط السلامة والخصوصية
- حفظ المحادثات محلياً **مُعطّل افتراضياً** ويُفعّل بإرادة المستخدم. البيانات في SQLite غير مشفّرة تشفيراً خاصاً، وليست مناسبة للأسرار. يمكن تصديرها أو حذفها بإجراء واضح.
- لا تُرسَل ملفات المعاينة إلى أي خدمة. فتح الملفات بإذن المستخدم عبر منتقي مستندات أندرويد من دون صلاحية قراءة تخزين واسعة.
- الإملاء يستدعي خدمة النظام/التطبيق المثبّت، وقد يتطلب إنترنت وفق إعدادات الجهاز. لا نطلب إذن تسجيل صوت دائم ولا نستمع خفية.
- مشاركة النصوص واستخدام لوحة الاتصال وفتح الإعدادات لا يحدث إلا بعد تأكيد المستخدم ثم الاستعانة بواجهة النظام، ولا يرسل التطبيق أو يجري اتصالاً بنفسه.
- القوالب ليست توليد وسائط بالذكاء الاصطناعي. أدوات الصور والفيديو الفعلية ما زالت غير منفّذة.
- حسابات API السحابية تتطلب رصيداً/حصة وموافقة المستخدم، ولا يوجد نموذج ضمن APK يعمل دون إنترنت. Ollama في النسخ الحالية موصول بكمبيوتر محلي فقط.
- لا يُدمج فرع التطوير في main ولا يرفع للتوزيع التجاري قبل اختبارات الهاتف وموافقة صاحب المشروع.

### منهج التحقق من هذه المرحلة
1. تشغيل `gradle :app:testDebugUnitTest :app:assembleDebug` على GitHub Actions.
2. فحص نتيجة النجاح ووجود Artifact الخاص بنفس commit.
3. فحص الهاتف خطوة بخطوة بحسب `docs/RELEASE_CHECKLIST_AR.md`.
4. أي مرحلة بلا اختبار على الجهاز تبقى مبدئية ولا تعتبر مكتملة قبولياً.
